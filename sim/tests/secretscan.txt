# secretscan: a password must not outlive its use anywhere in RAM.
# Run by `make -C sim secretscan` (CI gate). It types a Wi-Fi password through
# the real Settings screens, runs a (stubbed) sync that reads it the way the
# device does, and after each step scans the whole process's writable memory
# for it -- live buffers, freed heap, the LVGL pool, dead stack frames.
#
# (It used to type the iCloud app password too, through Settings > Accounts;
# that screen went with the iCloud sync, 2026-11-07. The Wi-Fi password goes
# through the same password editor, so every step it took is still taken.)
#
# The password is given ONLY in hex (K, X, Y, P), so neither this file nor
# stdin's buffer ever holds it in plain text. Don't write it out in a comment
# here either: the first run of this gate caught exactly that, a copy in
# stdin's read buffer. It is 39 characters, so that a copy freed without a
# wipe still leaves a long piece behind (host_main.c: SCAN_WIN). P checks the
# store really holds it, so an X that finds nothing means "wiped after use",
# not "never typed".
